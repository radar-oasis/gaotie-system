下面是一份可直接给前端/后端开发智能体使用的提示词，针对“颜色描述/颜色配置模块”。

---

## 前端开发提示词

# Role

你是资深前端开发工程师，熟悉 React、TypeScript、状态管理、Canvas/SVG 图形交互、图片取色、调色盘组件与复杂设计工具类界面开发。你需要为高铁涂装设计系统开发一个“颜色描述与配置模块”。

# Task Description

开发一个用于高铁布局方案色彩配置的页面。该页面承接“布局元素模块”中用户已选择或保存的布局配置方案。用户可以在左侧选择某一个布局方案，在中间区域对不同施色域进行颜色配置和文字描述，在右侧上传参考图片提取色板、使用调色盘选择颜色，并管理已保存的色彩方案。

# Page Structure

页面采用三栏布局：

1. 左侧栏：布局配置方案列表
2. 中间主区域：色彩描述与施色域配置
3. 右侧栏：色板提取、调色盘、已保存色彩方案

整体风格应与现有系统保持一致，清爽、克制、设计工具感强，避免营销式页面。

# Left Sidebar Requirements

左侧栏展示用户在“布局元素模块”中保存或选定的布局配置方案。

每个方案卡片包含：

- 方案名称
- 简略预览图或布局元素缩略图
- 方案中包含的施色域数量
- 当前是否选中状态

交互要求：

- 点击方案后，中间区域加载该方案的施色域
- 当前选中方案需要高亮
- 如果没有布局方案，展示空状态提示：“暂无布局方案，请先在布局元素模块中选择布局元素”

# Main Workspace Requirements

中间区域用于对施色域进行颜色配置和描述。

顶部展示当前方案预览：

- 高铁侧视图或布局示意图
- 用户选择颜色后，应在预览图上尽可能同步显示对应色彩
- 如果暂时无法实现精确区域上色，可以先以“区域标签 + 色块标记”的方式展示

色彩描述表单包含多个施色域行，例如：

- 车身主色
- 车窗带
- 腰线
- 车门
- 裙板
- 车顶侧
- 车头侧
- 自定义区域

每一行包含：

- 施色域名称
- 当前颜色色块
- 色值，如 `#1D4ED8`
- 颜色名称或语义描述，如“深海蓝”“银灰色”
- 效果描述输入框，如“用于强调车窗带的连续性与速度感”
- 删除按钮，仅自定义区域可删除

功能要求：

- 支持新增自定义施色域
- 支持从右侧色板选择颜色后应用到当前选中的施色域
- 支持点击色块打开颜色选择器
- 支持填写每个施色域的色彩描述
- 支持保存当前色彩方案
- 支持进入下一步“生成效果图与报告”

# Right Sidebar Requirements

右侧栏分为三块：

## 1. 图片上传与色板提取

用户可上传参考图片，系统提取主色板。

展示内容：

- 上传区域
- 上传图片缩略图
- 提取出的基础色板
- 配色方案分组

配色方案类型包括：

- 邻近色方案
- 对比色方案
- 互补色方案
- 单色渐变方案
- 主色/辅助色/强调色方案

展示方式：

- 每个方案以横向条形色板呈现
- 每个色块可点击选中
- 选中色块需要有明显边框或勾选状态
- 点击色块后，可应用到当前施色域

## 2. 调色盘

提供颜色选择功能：

- 色相/明度/饱和度调节
- HEX 输入
- RGB 输入
- 最近使用颜色
- 确认应用按钮

如果项目已有颜色选择组件，可复用；否则使用成熟库，例如 `react-colorful`。

## 3. 已保存色彩方案

展示用户保存过的色彩方案。

每个方案卡片包含：

- 方案名称
- 色板条
- 创建时间
- 应用按钮
- 删除按钮

点击“应用”后，将该方案颜色映射回当前布局方案的施色域。

# State Management

建议建立 `ColorConfigContext` 或局部状态模块，维护：

```ts
interface ColorRegion {

  name: string;

  description?: string;

interface ColorScheme {
  id: string;
  name: string;
  layoutSchemeId: string;
  regions: ColorRegion[];
  palette?: string[];
  createdAt: string;
  updatedAt?: string;
}

interface ExtractedPaletteGroup {
  type: 'analogous' | 'contrast' | 'complementary' | 'monochrome' | 'semantic';
  title: string;
  colors: string[];

```

# API Integration

需要调用后端接口：

- 获取布局方案列表
- 上传图片并提取色板
- 保存色彩方案
- 获取已保存色彩方案
- 删除色彩方案

接口失败时应有清晰提示，不要让页面静默失败。

# UX Details

- 当前选中的施色域需要高亮
- 色块 hover 时显示 HEX 值
- 保存方案前，如果没有选择布局方案，应提示用户
- 保存方案前，如果关键施色域没有颜色，应提示但不阻塞
- 页面不使用英文标题，全部使用中文
- 右侧色板区域要适合快速点击和比较颜色
- 颜色配置表单要保持紧凑，适合重复编辑

# Output Requirements

输出模块化 React 代码，建议组件拆分：

- `ColorConfigPage`
- `LayoutSchemeSidebar`
- `ColorRegionEditor`
- `TrainColorPreview`
- `ImagePaletteExtractor`
- `PaletteGroup`
- `ColorPickerPanel`
- `SavedColorSchemes`

确保 TypeScript 类型清晰，状态流稳定，界面可直接使用。

## 后端开发提示词

# Role

你是资深后端开发工程师，熟悉 NestJS、文件上传、图片处理、颜色聚类算法、REST API 设计和数据持久化。你需要为高铁涂装设计系统开发“颜色配置模块”的后端服务。

# Task Description

开发一组 API，用于支持前端颜色配置页面：

1. 获取用户已保存的布局配置方案
2. 上传参考图片并提取色板
3. 基于提取颜色生成配色方案
4. 保存用户的色彩配置方案
5. 查询、应用、删除已保存的色彩方案

# Core Data Models

```ts
interface ColorRegionDto {
  id: string;
  name: string;
  color: string;
  colorName?: string;
  description?: string;
  source?: 'manual' | 'palette' | 'image';
}

interface SaveColorSchemeDto {
  name: string;
  layoutSchemeId: string;
  regions: ColorRegionDto[];
  palette?: string[];
}

interface ColorSchemeResponse {
  id: string;
  name: string;
  layoutSchemeId: string;
  regions: ColorRegionDto[];
  palette: string[];
  createdAt: string;
  updatedAt?: string;
}

interface PaletteGroup {
  type: 'analogous' | 'contrast' | 'complementary' | 'monochrome' | 'semantic';
  title: string;
  colors: string[];
}
```

# API Design

## 1. 获取布局方案

`GET /layout-scheme/list`

复用现有布局方案接口。如果现有接口已存在，不要重复实现。

返回用户已保存的布局配置方案，用于颜色模块左侧栏展示。

## 2. 图片上传并提取色板

`POST /color-config/extract-palette`

请求：

- `multipart/form-data`
- 字段：`image`

返回：

```json
{
  "status": "success",
  "basePalette": ["#1D4ED8", "#93C5FD", "#111827"],
  "groups": [
    {
      "type": "analogous",
      "title": "邻近色方案",
      "colors": ["#1D4ED8", "#2563EB", "#0EA5E9"]
    },
    {
      "type": "complementary",
      "title": "互补色方案",
      "colors": ["#1D4ED8", "#F97316"]
    }
  ]
}
```

实现要求：

- 使用 `sharp` 读取图片
- 缩小图片尺寸后采样，避免大图处理过慢
- 提取主色时忽略透明像素、近白背景、近黑噪点
- 可以先实现简单 K-means 或颜色桶聚类
- 输出 5-8 个主色
- 基于主色生成邻近色、互补色、对比色、单色渐变方案

## 3. 保存色彩方案

`POST /color-config/schemes`

请求：

```json
{
  "name": "蓝白速度感方案",
  "layoutSchemeId": "layout_001",
  "regions": [
    {
      "id": "region_body",
      "name": "车身主色",
      "color": "#F8FAFC",
      "colorName": "冷白色",
      "description": "作为车身基础色，保持轻盈和现代感"
    }
  ],
  "palette": ["#F8FAFC", "#1D4ED8", "#93C5FD"]
}
```

返回保存后的方案。

## 4. 查询色彩方案

`GET /color-config/schemes`

支持可选参数：

- `layoutSchemeId`

如果传入 `layoutSchemeId`，只返回该布局方案下的色彩方案。

## 5. 获取单个色彩方案

`GET /color-config/schemes/:id`

返回指定方案详情。

## 6. 删除色彩方案

`DELETE /color-config/schemes/:id`

返回：

```json
{ "success": true }
```

# Storage Requirements

优先沿用项目现有存储方式。

如果当前项目布局方案已保存在 Neo4j：

- 可以创建 `ColorScheme` 节点
- 与布局方案建立关系：
  - `(ColorScheme)-[:BASED_ON]->(LayoutScheme)`
- 色彩区域可以作为 JSON 字符串存储在 `ColorScheme.regions`
- 色板可以作为 JSON 字符串存储在 `ColorScheme.palette`

示例属性：

```ts
{
  id: string;
  name: string;
  layoutSchemeId: string;
  regionsJson: string;
  paletteJson: string;
  createdAt: string;
  updatedAt: string;
}
```

# Color Algorithm Requirements

需要实现以下基础工具函数：

```ts
extractBasePalette(imageBuffer: Buffer): Promise<string[]>
generateAnalogousPalette(baseColor: string): string[]
generateComplementaryPalette(baseColor: string): string[]
generateContrastPalette(baseColor: string): string[]
generateMonochromePalette(baseColor: string): string[]
```

颜色转换工具：

- HEX -> RGB
- RGB -> HSL
- HSL -> RGB
- RGB -> HEX

# Error Handling

- 未上传图片：返回 400
- 图片格式不支持：返回 400
- 图片过大：返回 413 或明确错误
- 色彩方案不存在：返回 404
- 数据库存储失败：返回 500
- 图片解析失败：返回 500，并返回用户可读提示

# Security & Validation

- 限制上传文件大小，例如 10MB
- 只允许图片 MIME 类型
- 校验 HEX 色值格式
- 校验 `layoutSchemeId`、`regions` 不为空
- 不要信任前端传来的 `createdAt`

# Output Requirements

输出完整 NestJS 模块代码，包括：

- Controller
- Service
- 图片上传处理
- 色板提取逻辑
- 配色方案生成逻辑

- 单元测试

确保能被 `AppModule` 引入并运行。
