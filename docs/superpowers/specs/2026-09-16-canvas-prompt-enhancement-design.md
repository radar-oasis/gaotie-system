# 纹样转化提示词增强 v1：规则与设计依据

用户已在前几轮确认“API优化＋方向选择”路线，本轮明确要求详细规则并实施试用。只改纹样转化画布及相关服务，保留现有检索和画布改动，不做全库视觉识别、模型训练、自动生图或自动评优。

## 为什么采用这一方案

纯规则建议成本最低但只能覆盖少数表达；专用重写模型引入额外部署且没有本项目效果证据。采用现有文本模型API＋领域元提示词＋可解释检查，既支持模糊自然语言，也保留用户控制。首期模型只收到选中参考图的名称和已有元数据，不接收图片像素，不得冒充视觉识别。引用的开源项目仅借鉴思想，不复制其实现或大段模板。

## 拆解结构及规则

| 规则 | 具体约束 | 为什么符合本项目 | 参考 |
| --- | --- | --- | --- |
| R1 原意优先 | 保存原始输入，提取明确要求，增强不得覆盖原意；用户始终可恢复原文 | 设计师需要对比原文和增强效果 | Prompt Optimizer 原始意图优先的对比机制 |
| R2 修改与保留分开 | 解释目标对象、操作、变化程度、保留内容 | 本任务不是从零画新图，而是转化已有纹样 | Prompt Optimizer/Qwen 编辑任务拆解 |
| R3 保留母题身份 | 保留选中母题的可识别性，不擅自更换主体；无法从元数据确认的细节不编造 | 文化转译需要来源联系，名称不等于看图证据 | Qwen 参考一致性、项目图谱来源信息 |
| R4 感性词转形态 | 速度感可建议统一走势、渐收、横向延展；不能自动等同运动模糊 | 素材需要清晰边缘和车身排布适配 | Qwen 最少充分细化＋本项目领域假设 |
| R5 方向可选择 | 保留型轻度调整；探索型允许更明显抽象；两者保持用户明确条件 | 用户需求模糊、希望通过候选启发想法 | 编辑强度控制＋用户方向选择需求 |
| R6 图像角色明确 | 多张参考图只编号列出，未指定主次时提醒，不编造其构图关系 | 画布支持多图生成 | Qwen 多图引用关系 |
| R7 独立素材阶段 | 平面装饰元素，不画整车、轨道或场景；纯净背景供后处理 | 当前产物是车身设计元素，不是最终效果图 | 本项目生成/去背景链路 |
| R8 不强制风格 | 不擅加颜色、摄影词、阴影或纯填充要求；线描或填充尊重用户 | 避免默认后缀与用户线描需求冲突 | 最少改写原则、当前代码冲突 |
| R9 程序与模型检查分离 | 程序校验结构、字段/方向、长度；模型列要求与风险，明确未验证图像结果 | 防止“自评高分”被误当实际效果 | Prompt Optimizer文本/结果评估分离，混元逐考点 |
| R10 可复核而非自动取胜 | 显示原文/候选/保留项/新增建议；不显示虚构成功率；记录当前使用来源供用户对照 | 用户准备自行比较生成图片 | Promptist人工对比、混元原始考点评估 |

参考：[Prompt Optimizer 编辑模板](https://github.com/linshenkx/prompt-optimizer/blob/develop/packages/core/src/services/template/default-templates/image-optimize/image2image/image2image-optimize.ts)、[比较机制](https://github.com/linshenkx/prompt-optimizer/blob/develop/packages/core/src/services/template/default-templates/evaluation/image/text2image/evaluation-compare.ts)、[Qwen编辑增强](https://github.com/QwenLM/Qwen-Image/blob/main/src/examples/tools/prompt_utils.py)、[混元评测脚本](https://github.com/Hunyuan-PromptEnhancer/PromptEnhancer/blob/main/t2i_keypoints_eval.py)、[Promptist人工评价](https://arxiv.org/html/2212.09611#S3.SS4)。公开效果证据来自各自特定模型，不承诺迁移收益。

## 接口和交互

六个拆解维度分别是：①来源与参考角色（避免把多张图默认混合）；②主体、颜色等保留项（保护原意）；③修改对象与操作（明确究竟改哪里）；④变化方向与程度（区分微调和探索）；⑤走势、节奏等图形组织（把感受变成可画的描述）；⑥独立素材输出边界（服务后续车身合成，而非提前画整车）。这是领域编辑框架，不要求每次机械填满所有维度；信息缺失时列为不确定项。

POST /super-canvas/enhance-prompt
输入 {prompt:string, references:[{id,name,motifs?:string[],layouts?:string[],materials?:string[],carriers?:string[]}]}，最多8个实际选中的图层，按生图顺序传递；没有选中图层时不冒用素材库里的全部图片。
输出 {originalPrompt,ruleVersion,model,contextMode:'metadata-only',maxPromptLength,directions:[{id:'preserve'|'explore',title,prompt,retained:string[],changes:string[],checks:[{label,status:'pass'|'warning',detail}]}],warnings:string[]}。

独立面板提供“优化提示词”、正在优化/取消/失败重试、原文、两个可编辑候选、规则说明、应用和恢复原文。应用不触发生图；仍由原有AI转化按钮生成。输入、选中图层或项目改变则旧响应失效，不能覆盖当前编辑。候选超出实际正文预算禁止应用；服务端拒绝不合格响应，不静默截断；失败保留原文，无伪装成模型结果的硬编码候选。

首期候选在当前画布组件生命周期中保留；应用后的正文继续使用既有项目快照持久化。提供复制原文/候选方便人工记录，但不宣称已有自动A/B统计。不能用一张图证明稳定性。

独立素材后缀统一采用中性风格，取消强制填充/排斥线描。保留当前800字符发送预算，前端候选预算与后端拼接共享同样的明确上限；超过正文预算的生成请求应报错而非截断，最终整车生成行为保持原状。

## 验收

自动测试：请求结构/超长/空值，模型失败/无配置/超时/坏JSON/方向缺失/过长候选，真实原文保留，无额外图像上传，取消与过期响应，选择编辑应用与恢复不生图，线描后缀无冲突，原文与增强均不静默截断。构建与相关回归通过后检查本地页面。可做一次现有模型文本请求连通性验证，不调用生图收费接口。

人工评测：同参考图、同模型与参数比较原文/保留型/探索型，多次生成；按用户原意核验母题保真、形态变化、颜色约束、独立素材可用性，并记录费用/耗时和偏好。上线试用不等于效果已证实。

## 本次交付与验证（2026-09-16）

- 规则版本 `motif-enhancer-v1`；本地文字模型 `deepseek-chat`。候选正文预算575个UTF-16字符，与800总预算及中性后缀一致。
- 模型返回保留项、改动项和可选的本次不确定项；后者始终标记为“模型建议 · 本次待确认”，不允许冒充程序通过状态。多图时额外提醒明确参考角色。
- 前端29个测试文件、148项通过；后端24个测试套件、187项通过；两端生产构建通过。覆盖取消、过期响应、项目切换、参考变化、编辑应用、超预算、错误与原文恢复。
- 独立需求复核、代码质量复核完成；修正面板容器、具体领域规则、原文空白保留和情境不确定项。浏览器检查了窄工作区，新增候选收起入口，避免长期占用画布。
- 本地一次真实文字请求成功：输入“保留龙纹主体和红色，让它更有速度感、流线型，不要模糊。”，得到81字符保留型、91字符探索型；应用与恢复原文验证成功，未调用生图接口。本次无选中参考图，只验证文字链路；多参考真实出图尚待用户测试。
- 观察到保留型补充了“向右”这一未指定朝向，说明领域提示并不保证严格语义忠实；使用前应检查新增细节。这是本次试用的已知模型局限，不是经过证明的效果提升。
- 浏览器热更新后本轮临时对照已清空；用户可重新点击优化。原始测试输入仍在测试账号默认项目中，没有创建生成图片或删除用户数据。

建议每组原文、保留型、探索型各生成至少3次作为初步对照（不是统计显著性结论），固定参考图、模型及可控参数；若平台不支持固定种子，也应记录这一随机性限制。优先看是否满足原文、文化母题是否可识别和素材是否可用，再看个人偏好。
