# 通用高铁三维布局编辑与最终生图联动

日期：2026-09-17。状态：已实施七类区域与两节三维模型，已完成本地保存、刷新恢复、项目隔离、最终输入三视图加载验收；未调用付费生成。

## 1. 目标与范围

用户在可旋转的通用高铁三维白模上选择涂装区域与形式，以黑白灰预览大的色块布局。保存后可以恢复编辑；最终生图接收同一版本的布局参考、已转化纹样及配色，形成整体涂装。

首版不追求特定车型工程精度，不做三维自由绘画或逐车厢差异设计，不声称生成模型能像几何渲染器一样严格复现每个边界。

## 2. 通用模型与区域交互

- 使用程序化生成的真实可交互三维几何，不以一张AI生成的白模图片冒充三维模型。通用流线车头、圆角车体、车窗、车门、轮组应可辨识。
- 首版仅采用一节头车与一节普通车厢组成的两节示意模型，不另加尾车。说明其用于展示连续关系，不代表实际编组或工程尺寸。两侧布局默认镜像。
- 支持拖拽旋转、缩放、侧视/正视/俯视/斜前视和视角复位。悬停只高亮与提示，点击锁定编辑区域，拖拽旋转不能触发布局选择。
- 面板与模型双向联动；细腰线和遮挡区域可以通过面板选中，提供键盘可操作的区域与形式选项。
- 模型基础白色，涂装区域使用固定灰阶与边界提示；玻璃、灯具、轮组保持独立材质，不作为任意涂装面。编辑高亮不写入保存参考图。

## 3. 第一版形式与覆盖规则

| 区域 | 形式 | 范围与默认规则 |
|---|---|---|
| 车窗带 | 无、长带、短带 | 长带沿两节可涂车体连续，车厢连接处自然断开；短带在各车厢客窗段起止，不覆盖驾驶室玻璃；可选跨门或避让门 |
| 车门 | 跟随布局、整门涂装、上半门涂装、保持白色 | 默认全部客室门同一规则；整门涂装仍保留门窗玻璃 |
| 腰线 | 无、单线、双线 | 提供细/中/宽三个预设，两条线保持间隙；默认在门处避让，可切换跨门 |
| 车头 | 无、整鼻区、鼻尖上部、鼻尖下部、仅正面 | 整鼻区为驾驶室风挡以下的可涂鼻部，含左右侧面；上/下按鼻部中线分区；仅正面不延伸至侧部。区域示意与模型预览共同解释边界 |
| 车底侧（裙底板） | 不涂、涂装 | 固定裙底板实体范围，只切换是否涂装，不增加宽窄、线数或形状选项；轮组及非车体部分不纳入 |
| 下车底区（窗下区域） | 不涂、窄幅、宽幅 | 区域边界为车窗带/窗框下缘至裙底板上缘之间的车体侧面；宽窄指上下方向覆盖高度，不指沿车长方向的长度，也不是裙底板宽度 |
| 车顶侧（窗上区域） | 不涂、窄幅、宽幅 | 对应用户所说的“上车底区”，范围为车窗带上缘至车顶边界之间的车体表面；宽窄指上下方向覆盖高度，不改变实体车顶或车窗尺寸 |

窗上、窗下区域始终存在于模型定义中，即使车窗带选择不涂装，也以固定窗框带边界作为定位基准。窄幅/宽幅只改变涂装遮罩，不拉伸模型几何。首版约定窗上色块自车顶边界向下展开、窗下色块自裙底板上缘向上展开，窄幅覆盖各自可用高度的三分之一，宽幅覆盖全部可用高度；该比例是实现预设而非用户提供的工程尺寸，可在预览验收时调整。

渲染与导出共用同一遮罩规则：白色基础 → 窗上/窗下区域与裙底板 → 车窗带 → 腰线 → 车头形式 → 车门独立规则 → 不可涂部件。窗上/窗下大色块与腰线重叠时，腰线仍保留独立形态与可识别灰阶。车门为“跟随布局”时继承所在大色块，并保持带线跨门/避让设置；独立整门、半门或白色选项覆盖门上背景及带线规则。双线作为两块分离涂装几何，不以粗线假代。

全部七类区域均纳入首版三维交互、灰阶预览、方案保存恢复和最终生图，不将新增三类留在二维入口。旧版二维方案仍保留兼容入口；不得凭编号猜测旧图片对应的新三维形式。页面名称采用“车顶侧（窗上区域）”“下车底区（窗下区域）”“车底侧（裙底板）”，使旧分类与用户描述对应。

## 4. 方案保存：配置、图像和版本必须一致

- 扩展现有LayoutScheme，保留id/name/projectId/componentsMap等兼容字段。新增带版本号的layout3d配置，包括模型版本、各区域形式与范围、覆盖规则；三维方案不伪造A1/B1等旧二维编号。
- 保存时冻结当前配置，从同一模型生成无控件、无高亮的参考图。首版至少包含整编组侧视图、头车斜前视图和车头正视图，以覆盖连续关系、侧面延伸和正面边界。
- 后端校验配置、图像类型及大小，图片落到项目关联的持久资源位置。配置与参考图全部成功持久化后，才能反馈保存成功和设为当前方案；失败保留草稿，不能把缺参考图的方案用于生图。
- 每次“保存为新版本”生成独立方案，不默默改写旧版本。缩略图列表支持命名、加载、选用；恢复后准确显示所有形式。
- 模型版本和配置摘要与参考图一起记录；导出期间修改配置应阻止保存混合版本或要求重新保存。后续编辑标记为未保存，不自动改变已选方案。
- 项目切换取消旧项目请求并隔离状态；旧版二维方案可继续查看和使用，不自动推断三维形式。

## 5. 最终生图设计包

复用当前FinalDesignPackage与参考图清单机制，三维方案附带完整配置、版本和布局参考图。最终页面明确展示当前选用的布局版本与参考缩略图，允许回到布局模块修改。

各输入职责：

- 三维布局：约束大色块位置、连续/断开、门区域覆盖、单/双线、车头范围、裙底板是否涂装及窗上/窗下色块覆盖高度；灰阶只是区域编码，不是最终颜色。所有七类配置均进入文字说明与参考图。
- 转化纹样：优先使用用户选择的已生成纹样或含该纹样的画布截图，保留其身份与构图意图；不得默默用原始检索纹样替代已转化素材。
- 配色：延用当前已选配色方案，兼容整体配色参考和已有区域配色模式；没有配色时默认保留灰阶参考，而不捏造配色选择。本次明确的文字颜色要求优先，不从案例或纹样自行引入颜色。
- 案例：只影响允许参考的风格，不覆盖用户已保存的布局和纹样。

冲突时，已保存布局决定大色块与禁涂边界，画布提供纹样身份、方向和相对位置；纹样需适配布局区域，不能通过重画车窗带来解决冲突。若用户本次明确要求改变已保存结构，应在生成前说明与所选版本不一致，不静默宣称仍严格使用原布局。

必须移除当前提示中不分选项地要求车窗带“连续贯穿”的逻辑，改为从配置生成文字。所有启用的生图提供方共享配置语义与附件清单，避免仅接通其中一路。

三张布局图计入现有参考图数量上限；超限时清楚提示用户减少其他参考，不自动舍弃布局图或已选转化纹样。参考图读取失败时不发送付费生成请求。只保存和预览布局不触发生图。

输入指纹、归档快照和历史版本必须包含三维配置和参考图版本，使修改门覆盖/线数等操作会标记旧效果为过期，但不破坏历史结果。最终生成遵循参考，不承诺像素级布局一致。

## 6. 实现边界与故障处理

分为配置与遮罩规则、模型与交互、参考图导出、方案持久化、最终设计包适配五部分。渲染、预览导出与说明文本使用同一配置定义，避免各自解释选项。

WebGL不可用时显示说明并保留已保存参考图和旧二维入口，不展示伪三维结果。页面退出释放图形资源。保存、载入、导出分别显示状态与可重试错误；资源丢失不允许以旧图假装当前配置。

## 7. 验收标准

1. 模型可旋转观察正面与侧面，区域选择与旋转不冲突，玻璃和灯具不被覆盖。
2. 模型仅包含一节头车与一节普通车厢。长/短窗带、跨门/避门、门形式、单/双腰线、五种车头选项、裙底板涂/不涂及窗上/窗下窄幅/宽幅在灰阶预览中可辨识；组合符合统一覆盖规则。窗上/窗下宽度不会改变车窗或车体几何。
3. 保存、刷新、重新打开及切换项目后，配置与参考图保持对应；失败保存不丢失当前草稿。
4. 生图请求的实际附件包含所选版本布局图和已选转化纹样/画布参考；提示准确表达短带、断门、双线、正面范围、裙底板状态及窗上/窗下覆盖高度，不复制灰阶为最终色彩指令。
5. 配置变化使输入指纹变化，历史快照不变；旧二维方案及现有配色模式可继续使用。
6. 自动化覆盖配置组合、遮罩优先级、保存恢复、异常与请求组装，浏览器检查侧/正/斜视、图片导出与布局版本选用。默认使用模拟生图服务验收，不自行发起付费整车生成。
