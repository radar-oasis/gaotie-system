# 纹样分组检索与分类灵感扩展实施计划

目标：落实用户已确认的低成本优化，修复图谱字段，保留各意象结果，利用既有分类提供可解释的相关灵感。

设计：前端自动检索直接传递已确认的结构化意象，避免让模型再次合并它们。手动自然语言查询仍保留解析，但失败可按分隔符检索；朝代、材质、载体、组织形式作为明确条件。后端新增 grouped-query，兼容旧 query。所有素材用 Pattern_ID 去重；同一个素材可属于多个分组。每组区分 direct / related，各自总数、加载更多。分类推荐文案明确是灵感扩展，不是感受事实。

接口：POST /image-search/grouped-query，body 为 {motifs,dynasties,materials,others,carriers?,layouts?,groups?:[{id,label,keywords:string[]}],page?:{groupId,kind:'direct'|'related',offset},limit?:number}。

返回 {patterns:Pattern[],groups:[{id,label,keywords,directTotal,relatedTotal,directIds,relatedIds}]}。
Pattern 在现有字段之外提供稳定 id、motifs/materials/carriers/layouts/categories、matches:[{groupId,kind,reasons:string[]}]。首次各组取40条；page请求只返回该分组指定kind的分页。前端增量合并并保留另一种结果，支持最多40条每次继续加载。实际图库总量不是已加载量。

实现任务：

- [x] 后端：从真实图字段读取完整元数据与分类，分维度匹配；按组生成直接命中和同类/抽象分类扩展；排序、可解释理由、分页、稳定ID；Jest覆盖漏检、AND约束、多组、分页及扩展边界，真实Neo4j只读验收。
- [x] 前端：结构化意象入口、请求取消与旧请求隔离、失败回退、上下文与快照兼容；分组切换、直接/灵感切换、计数、继续加载、命中理由及分类标签；Vitest覆盖分组、去重、恢复、失败。
- [x] 集成：前后端构建、相关回归测试、实际API的龙/云/类别/朝代/材质检索、UI检查及独立审查。

实现顺序：先写能复现旧问题的测试，再实现后端和前端契约，最后整体验证。仅增加代码与必要文档，不变更图谱原数据、不安装视觉模型、不创建付费模型测试请求。已有脏工作区保留；直接更新用户正在使用的本地项目，不自动提交。

## 当前边界

感性方向是小型可维护规则（吉祥、喜庆、庄严、神兽、瑞兽），不做视觉情感识别；“速度感”等无规则、无图谱直接命中的词不会随意返回全库。分类联想受原图谱分类质量影响，不代表客观文化寓意。手动自然语言查询仍使用现有解析服务；已选结构化意象直接检索，不再重复调用解析模型。12k图库采用60秒元数据缓存，增量变更可能延迟最多60秒反映；后续数据规模大幅增长时再考虑独立索引。
