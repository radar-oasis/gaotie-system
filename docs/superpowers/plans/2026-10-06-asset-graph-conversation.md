# 资产图谱对话检索实施计划

**目标：** 将知识图谱设为资产沉淀默认入口，支持按项目、方案、纹样进行模型理解后的对话检索；统一自动命名并拆分布局区域样式。

**架构：** PostgreSQL保留资产权威记录，Neo4j根据保存信息自动重建关联。模型只输出受限查询意图，服务器验证并执行有账号边界的查询，不运行模型提供的Cypher。图谱默认展示完整可用节点，超过安全上限明确提示缩小范围。

**技术：** 现有React、Nest、PostgreSQL、Neo4j、已有模型接口。

- [x] 前端调整页签顺序和默认页；单个对话输入，保留当前会话上下文、加载、失败重试、回到完整图谱；移除跳数控件。
- [x] 后端增加对话意图解析与受约束检索；项目/方案/纹样条件取交集；未知实体不返回全部；仅从真实关联解释结果。
- [x] 布局图谱表达方案→布局→实际采用区域样式。长窗带命名连贯型，短窗带命名分段型。默认未涂装和继承状态不生成采用节点。
- [x] 新生成/收藏纹样根据原始纹样名称分配序号；同图重复收藏保留编号。回填当前示范资产和项目图层，保存修改前备份。
- [x] 检查新增方案后图谱自动变化、用户隔离、模型失败、复合检索、追问、命名幂等及多区域布局；真实模型和浏览器验收。

用户已明确要求开发上述交互，直接在现有工作区实施，不清理已有未提交工作。


## 实施与验收记录

- 知识图谱为第一个页签和默认入口；移除跳数控件，保留单个对话输入、连续追问、失败重试、完整关系恢复。
- `POST /assets/graph/chat` 使用现有 DeepSeek 配置解析意图，后端校验当前账号目录后查询 Neo4j。项目、方案、纹样条件组合，未知实体不扩大检索范围。
- 布局关系为方案→布局→实际选定区域，长窗带显示连贯型。实际三区域配置已通过 API + Neo4j 集成验证。
- 图谱身份使用实际图片或明确收藏 ID。裁剪共享祖先 URL 不合并；持久参考副本保留来源收藏 ID。已增加单裁剪、删除后误关联及多方案裁剪独立性测试。
- 命名使用原始纹样全名和序号；收藏后采用后端分配的稳定编号。PostgreSQL 并发分配验证覆盖 8 个重复请求、不同图片、删除后重新收藏。
- 示范项目两张图和方案引用已回填为 `唐李嗣本墓志上的石刻十二生肖之龙纹-1/-2`，按实际 PNG 字节核对后关联透明纹样与示范方案。修改前备份位于 `tmp/pattern-name-backups/`；再次 dry-run 无待修改内容。历史关联补录说明保留。
- 浏览器真实模型验证：默认项目有哪些方案；追问采用哪些纹样；按原始龙纹名称检索，返回原纹样→转化纹样-2→示范方案。
- 后端全量 53 suites / 463 tests 通过；身份关联修正后资产相关 7 suites / 51 tests 通过。前端相关 10 files / 74 tests 通过；前后端构建通过。Vite 仍提示现有大包体积建议。
- `scripts/verify-assets.js` 使用临时账号通过保存/删除后的 Neo4j 自动同步（在任何图谱 GET 前直接读取 Neo4j）、三区域关系、账号隔离、来源副本、重复保存和重新收藏验证，结束清理临时账号。

- 最后补充收藏名称回写的卸载/切项目防护，两项先失败后通过的回归覆盖延迟成功响应；收藏按钮与画布相关 30 项测试通过。

## 方案图谱视觉统一

按后续反馈，用户入口改为“方案图谱”；直接复用纹样检索的 NativeGraphCanvas，包括圆形节点、点阵背景、拖拽弹性跟随、平移、缩放与适应画布。对话使用共同 workspace-composer / workspace-send 样式和上箭头按钮，支持 Enter 提交、Shift+Enter 换行，中文输入法确认不误提交。

修复共享画布在 StrictMode 首次挂载尚未排布完成时保存临时坐标，导致第二次挂载冻结重叠节点的问题；保留完成布局后的坐标与视角。相关4个测试文件30项通过，目标 ESLint 和前端构建通过，浏览器截图验证布局与输入框。

实查 `CALL db.info()` 返回默认数据库 `neo4j`；方案图谱使用既有本机 `bolt://localhost:7687` 服务，没有新建 Neo4j 数据库。`DesignAssetNode` / 具体设计节点标签与 `ownerId` 区分个人资产；PostgreSQL 保留资产原始记录。
