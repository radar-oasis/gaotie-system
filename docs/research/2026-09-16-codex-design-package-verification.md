# 本地 Codex 生图与多图设计包验收

## 已实现的链路

本地 `.env.local` 的 `LOCAL_CODEX_IMAGE_ENABLED=true` 同时启用纹样转化与最终效果的 Codex 通道。关闭此开关即可恢复原供应商配置；不自动重试、不自动切换供应商。本次没有修改线上环境。运行后端仍须本机 Codex 已登录且具备图像生成能力；无需把登录令牌或 API Key 复制进项目。

纹样转化：参考图实际读取为图片 → Codex → 现有透明背景处理 → 画布素材。

最终效果：同一份有序清单同时生成附件与提示词，整车结果不做去背景。

| 角色 | 用途与优先级 |
| --- | --- |
| 上一版效果（微调时） | 作为调整基底，保持未要求修改的部分 |
| 所选画布截图 | 车辆形态、视角、已转化纹样身份与布置位置 |
| 每个选中布局的图片 | 对应部件的结构约束；车窗带明确要求连续贯穿 |
| 每个案例图片 | 对应用户的借鉴说明；不能自行替换车型或覆盖布局 |
| 纹样原图（没有截图时） | 素材兜底，不在已有合成截图时重复叠加原图 |
| 色卡 | 颜色参考；区域和色值由文字绑定，不绘制色卡本身 |

布局编号仅用来定位素材文件。生成文字不直接包含内部组件编号，不再把 `车窗带:A2` 当成视觉要求。截图、布局和案例可能朝向不一致，因此提示词明确以画布外形与视角为主。生成结果仍具有随机性，文字约束不能保证像素级布局一致。

## 上传与安全边界

- 最多 12 张附件，超限明确报错；任何一张无法读取都在调用模型前停止，不会以部分图片继续生成。
- 支持本系统素材路径、当前后端本地源、明确配置的本系统素材源（映射本地文件），以及上传产生的 PNG/JPEG/WebP data URL。
- 每图最大 20 MB、4000 万像素，加载后按比例压到最长边 2048。HTTP 请求体仍受系统 30 MB 总上限约束；多张大截图需先压缩。
- 任意外站图片 URL 暂不由后端下载，避免内网访问风险；需先上传到本系统。现有案例图库的 `/sample-images/` 已支持。
- 仅允许本机连接、可信本地 Host/Origin、已登录会话。Codex 单并发、240 秒超时；不将此方案作为多人线上生图服务。
- 前端取消/连接提前关闭会向 Codex 传递取消信号；正常请求体读取完毕不会误触发。取消会停止尚在运行的任务，但不能撤销此前已经发生的额度消耗。
- 关闭 shell、浏览器、插件等能力，动态禁用继承的每个 MCP 服务，并在生成前核实 disabled/零工具；不复制凭证，不信任模型返回的任意文件路径。
- “邮轮”旧静态演示分支改为显式 `VITE_ENABLE_CRUISE_MOCK=true` 才开启，默认走真实生成。
