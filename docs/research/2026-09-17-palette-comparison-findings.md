# 提色算法与配色提示词对比实验

日期：2026-09-17。独立实验；未替换业务算法、改动正式依赖或数据库。

## 原服务究竟是什么

上一轮调用的是当前系统 ColorPaletteService：图像缩至最大 120×120，RGB 按 16 步长量化、统计出现次数、取前 8 色，过滤透明、近白和近黑像素。ColorConfigService 直接取第一个颜色，通过 HSL 色相和明度变换生成邻近、互补、对比、单色方案。这里没有大模型提示词。

最终效果图的 PromptComposerService 是另外一层，含“色彩必须按区域执行”等约束；这次实验没有调用或改写它。上一轮搜图提示词是本次实验自行编写的检索指令，不来自 GitHub 配色项目。

## 算法实验

用上一轮相同的 3 张青花盘图，另加白、黑、灰三个控制样本。各算法接收同一份最大 120×120 的图像。ColorThief 3.5.0 使用 OKLCH、8 色、quality=1、ignoreWhite=false；Material Color Utilities 0.4.0 使用 Celebi 量化 8 色，再测试默认 Score（desired=4）。当前系统保持自己的过滤策略，因此是完整候选配置比较，不是单独隔离聚类算法的比较。

- 青花盘一：当前已提取蓝色，不能宣称开源算法在所有样本上更好。
- 青花盘三：当前第一色 #f0f0e0；ColorThief 第一色 #7893b4，另提供深蓝 #274485；Material 默认评分第一色 #6e87af。对于“选择蓝色作为纹样主色”的需求，新候选更直接，但不证明自动识别了纹样主体。
- 青花盘二：ColorThief 第一色 #040403，Material 默认评分第一色 #e3ebea，说明换库后仍不能机械地拿第一色作为设计主色。
- 白与黑控制图：原服务抛出 No usable colors extracted from image；ColorThief（保留白色）与 Material 量化返回正确的白、黑。
- 灰色 #888888：原服务量化成 #909090，两种开源量化返回 #888888。
- Material 默认 Score 对白、黑、灰都返回 #4285f4（默认 Google Blue），并非原图色。必须单独处理无彩色场景，保留中性色，禁止未标记的兜底色混入“提取色”。

当前 Node 25.2.1 下 Material 0.4.0 根入口出现 ESM 无扩展名导入错误；实验改为只导入量化、评分、HCT 等具体组件后运行成功。因此还不是直接接入生产可用的结论。

## 提示词实验

两次独立、本地 Codex 调用，均关闭联网与额外工具，使用相同默认模型配置；本次未记录具体模型版本。没有上传图片，仅传入提取色板。每个提示仅运行一次，不构成稳定性或审美统计评估。

共同输入：

> 主题：青花龙纹，高铁涂装，清雅、现代。已提取真实候选颜色：["#7893b4","#274485","#f5f3ee","#797ba4","#d6dcdb","#ccd8dd","#adaa9e","#e8e1ca"]。用户锁定纹样蓝色 #274485，不允许改变。未提供图片，不得声称看过图。不要使用工具。

A 普通提示（本次自行编写，不是系统现存提示）：

> 请提供一套好看的配色方案，给出颜色、比例和理由。只输出 JSON。

B 约束提示（本次自行编写，不是 GitHub 项目的提示）：

> 你负责选择和解释配色，不负责估计像素。只从候选色中选择，不新增颜色；必须保留用户锁定色。输出单个 JSON 对象，含 colors 数组（3项，每项 hex、role、proportion）、rationale、limitations。role 分别为底色、纹样主色、辅助色；proportion 为整数且合计100，代表设计建议而非图片面积测量。保持青花蓝白关系，不因为邻近色规则引入紫色作为主题主色。理由区分用户主题意图与已知颜色数据，不断言庄严吉祥等文化感受已被验证。limitations 明确未看图及比例不是测量值。

实际结果摘要：

| 观察 | A 普通提示 | B 约束提示 |
|---|---|---|
| 输出配色 | #f5f3ee 65%、#ccd8dd 20%、#274485 12%、#7893b4 3% | #f5f3ee 75%、#274485 20%、#ccd8dd 5% |
| 保留锁定色 | 是 | 是 |
| 只使用候选色 | 是 | 是 |
| 比例合计 | 100% | 100% |
| 明确声明未看图 | 未在输出中明确声明；未声称已看图 | 是 |
| 明确比例不是测量 | 给出涂装可见面积的比例口径，但未明确写不是测量值 | 是 |
| 结构 | 自选中文字段、4 色 | 按约定字段、3 个角色 |

不能将 A 未按 B 的格式输出说成 A 失败，因为 A 未被要求遵循此格式。B 的优势是契约清晰、便于页面呈现与校验、区分建议和事实，不是已证明更美观。A 这次同样正确遵守了锁定色等共同要求。

## 建议

优先验证 ColorThief 提取候选色，保留中性色；用户或受约束的模型选择主辅色，不能总取第一色。比例作为设计建议，颜色出处标记为“原图提取”或“规则推导”。模型输出仍需代码校验候选集、锁定色、比例和结构，不能仅靠提示词保证。Material 的色调能力可另外评估，不直接照搬其面向 UI 的默认主题筛选。

只有 3 张同主题照片，未做跨主题样本、多人盲评、模型重复试验、最终效果图生成或实际涂料色差验证。所有“更好”仅限上述观察。
