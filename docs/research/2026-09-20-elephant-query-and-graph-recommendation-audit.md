# “大象”漏检与知识图谱推荐能力核查

日期：2026-09-20。范围：用户提供的文化知识图谱构建目录、当前本地 Neo4j、正在运行的 grouped-query、当前检索源代码及算法官方资料。仅做只读诊断；没有修改业务代码、运行导入脚本、写入图谱或安装算法插件。

## 研究问题与证据边界

决策：下一轮应先修复查询理解、补充数据，还是引入图算法？核查三个假设：分类未导入；查询未识别同义词；已有关系不足以支撑推荐。以原始关系文件与数据库逐条比对、真实接口复现、源代码调用链为停止条件；算法建议由官方文档及原始论文支持，不冒充本库实测效果。

数据库关系只证明系统存了什么，不证明图片实际包含该内容。返回条数不是召回率；本次未重新运行完整前后端测试，也未进行视觉人工标注或算法效果实验。9月16日的通过记录不能替代本次新增问题的回归验证。

## 1. 已复现的根因

同一运行中的 grouped-query，直接以 motifs 数组传入，排除自然语言解析模型的随机影响：

| 输入 | 直接结果 | 相关灵感 |
|---|---:|---:|
| 大象 | 0 | 0 |
| 象 | 521 | 722 |
| 野生兽类 | 804 | 0 |
| 动物与神兽 | 3069 | 0 |

当前词语归一化只有少量别名，如祥云→云、凤凰→凤，没有大象→象。匹配方式主要为“字段文本是否包含完整查询词”，因此“象”不包含“大象”，既不能命中母题，也无法从母题出发扩展类别。

反方向的问题同样重要：“象”也命中了天象、水象与气象、自然景象，以及物象、事象。接口实际出现了仅因分类含“象”而进入直接结果的“龙纹朝服”“海屋添筹纹”等。当前数据库显式关联 Motif=象 的素材为42条，但该数不是人工核定的真实大象图片总数。

因此不能只增加一个别名就认定问题解决：那会让“大象”也继承宽泛单字匹配的噪声。应先把查询对齐到明确的母题实体，再按实体关系召回；分类检索与母题检索分开解释。不能简单删掉“大”或随意拆字，否则“大雁”等词也可能被错误处理。

## 2. 分类不是没有导入，但原始信息并未全部建入图谱

原目录：/Users/lisensen/毕业论文/高铁智能助手/文化知识图谱-构建。

L1_to_L2.csv的33条关系、L2_to_L3.csv的1168条关系与数据库逐条一致，没有缺失或额外关系。原文件明确包含“野生兽类,象”，图中也存在“动物与神兽→野生兽类→象”。

现有核心结构：

```text
Level1 → Level2 → Motif ← Pattern
                              ├→ Dynasty
                              ├→ Material
                              ├→ Carrier
                              └→ Layout
```

实际有10个Level1、35个Level2、1168个Motif、12080个Pattern；17212条CONTAINS_MOTIF关系。9379条Pattern有母题关系且能够连接到Level2；2701条无母题关系，无法通过该路径扩展。原CSV中“标签_处理后”恰好9379条非空，与导入逻辑吻合，不能把全部缺失归因于数据库导入故障。

另有“杂项服饰”“其他”两个Level2没有Level1父节点，这与原L1_to_L2.csv本身不覆盖这两个类别一致。它不导致“象”的路径断裂，但完整上层分类浏览需要处理。

原CSV还存在另一种“纹样类别”：单独纹样、综合纹样、适合纹样、连续纹样、边饰纹样、满地纹样。这与“动物与神兽→野生兽类”是不同分类维度，也不等于当前Layout里的单独式/复合式/其他。不能因名称相近就合并。

|---|---:|---|
| 图案介绍 | 11973 | 未存入Pattern属性，也没有对应内容节点 |
| 纹样类别 | 11590 | 未建立这一独立分类维度 |

neo4j_import.py将Pattern节点导出为Pattern_ID、名称、公元纪年、图片链接四列，build_knowledge_graph.py也仅创建这四个属性；数据库属性核查一致。因此现有信息损失发生在导出/建模选择，而不是检索时所有原字段都已经可用。

原“图案介绍”有5条文本出现“大象”，但有些是复用的傣锦背景介绍，不能把全文提到的大象直接当作每张图都具有大象母题。比如“傣锦的屋顶纹”的介绍同时说明孔雀、大象、建筑，其标签包含象、景谷、傣锦等；这些可能混合了主体、地域、工艺和背景。是否实际误标仍须看图确认，但“背景提及”与“主体包含”目前没有被区分，是算法效果的实质风险。

## 3. 当前到底用了哪些图关系

已经使用Pattern到母题/朝代/材质/载体/构图的关联，以及母题所属Level2/Level1的关系。后端读取并缓存这些关系得到的元数据，在应用层做匹配、排序和同类扩展。

所以不能说完全没用图关系；但也不能将它称为成熟的图算法推理系统。当前更准确的定位是“利用图谱关系的属性检索和分类扩展”。未发现GDS过程（本地SHOW PROCEDURES返回gds.*为0），当前未接入GDS算法。这不妨碍使用Cypher或应用代码实现路径检索、共现计数与局部相似度。

## 4. 现有关系能支持的应用

### 优先：实体对齐与指定路径检索

将“大象”“象纹”等检索用语映射到稳定的Motif实体；对有歧义的词让用户确认，对不能识别的词提供已有词表建议，不让模型自由创造实体。

再区分不同推荐目的：Pattern→Motif←Pattern用于同母题素材；Motif←Pattern→Motif用于素材中的组合；Pattern→Motif←Level2→Motif←Pattern用于同类探索。路径不同，推荐理由不同。PathSim研究支持这种在异构图中显式区分路径语义的做法，但本项目无需先完整实现PathSim才能利用这些路径。

### 优先：已选素材的属性相似推荐

用户选中一张素材后，依据共享母题、构图、载体等推荐其他素材。可分属性计算Jaccard等相似度，再按任务加权；同朝代或同材质只能作为辅助，不应与同母题等价。Neo4j Node Similarity提供基于邻居集合的相似性计算，但它不是图像视觉相似度。

先对当前素材与有限候选计算，再考虑离线索引。不能因为素材只有约1.2万条就假设全量两两计算可实时运行；topK返回限制也不等于免除前面的配对计算。

### 可做：母题组合推荐

现库有4769条素材关联多个不同母题，支持计算真实录入关系中的共现。以“象”为起点，当前共现计数包含房屋6条、佛5条，也包含景谷、傣锦等疑似混合类型标签。可见组合推荐有数据基础，但原始共现不能直接解释成文化寓意或设计搭配规律。

应区分主体与背景、按素材对象去重、考虑母题频率和最小支持度，再给出“这些元素曾在本库素材中共同出现”的说明。

### 后续实验：以用户选中素材为起点的Personalized PageRank

可以将当前选择作为种子，在受限关系范围内多跳传播，综合多个选择寻找关联素材。需要设计反向/无向投影或其他可返回Pattern的路径，否则现有单向Pattern→属性边会走到终点；也应对普遍属性降权，避免共同连接到一个大类就认为强相关。

实际Layout=复合式连接5374条素材，单独式连接4943条。它们若被当成与稀有母题同样重要的连接，会引入大量弱关联。建议先测试指定路径、局部相似度，再比较PPR的增益。

### 暂不作为主线：社区发现、图嵌入和链路预测

可以辅助素材分群或提供待审核缺失标签候选，但目前没有证据表明优于简单可解释基线。聚出的群不能自动命名为文化流派；结构嵌入不等于视觉理解；没有寓意关系和来源证据，就不能据此预测可靠文化寓意。若算法主要恢复既有分类，新增价值有限。

## 5. 图数据库是否比普通数据库更有优势

固定属性筛选及少量同类查询，关系数据库通过关联表也能完成；本次没有性能对比，不能宣称Neo4j天然更快或不可替代。

现图谱更有潜力的价值是：明确区分多种实体关系，按不同路径组合检索，将推荐理由追溯到路径，未来能增量加入有来源的文化语义、组合和使用语境。这是数据模型和应用方式的优势，不是换成图存储就自动产生的优势。

当前更像“分类与素材属性图谱”，足以做关联推荐，但不足以独立完成文化寓意或视觉感受推理。未来若需要这些能力，可补Concept、Motif、Composition、Meaning、Source等有明确语义的节点/关系；例如某种组合在特定语境下被某文献解释为何种含义，并记录来源、审核和置信边界。不要仅为运行算法新增无证据关系。

## 6. 建议顺序与验证方法

1. 先做统一实体识别：规范词、别名、歧义处理与字段边界；同时覆盖大象/象、凤凰/凤等正例和天象/物象等负例。已选意象和手动查询共用这层逻辑。
2. 做数据补全审计：保留原说明文本及独立纹样类别，核查2701条缺母题记录；区分“包含”“背景提及”，不要直接全库自动生成标签或重跑旧导入脚本。
3. 做指定路径和局部相似度原型：同母题、同类、同构图、共现分别显示，记录依据和可撤销筛选。与现有分类扩展在相同任务下对比。
4. 只有收益明确时再试PPR或图嵌入。用人工判断的前若干结果可用率、长尾覆盖、重复率、首个可用素材耗时验证；不只看返回总数，也不只看恢复被随机隐藏标签的能力。

结论修正：最初“可能分类没导入”的假设被逐条比对否定。问题主要是日常词到图实体的对齐缺失、跨字段字符串匹配过宽，同时存在源信息未保留、标签覆盖及语义质量问题。图算法不能替代前两项基础工作，但实体识别与关系质量明确后，现有多母题数据足以支撑更实用的关联推荐。

Evolution Note：今后检索验收应从“接口有结果、分类可扩展”升级为“实体识别正确、负例不串类、路径可解释、原始说明与主体事实区分”。本次尚未形成算法增益的实证结论。
